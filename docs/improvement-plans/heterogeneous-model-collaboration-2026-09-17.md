# 异构模型协作：交接、纠偏与评测方案

日期：2026-09-17。状态：文档与 Skill 已实施；真实验证未执行。核对基线：`a9b494a`。

用户已授权方案后的文档与 Skill 实施；真实派发、部署和评测未获本轮授权。现行规则以已更新的 Skill 和 AGENTS.md 为准。历史方案与验证结果保留其当时事实。

## 目标与现状

主要使用场景是：强主模型负责目标理解、关键判断、任务拆分和最终验收，合适的低成本子模型承担有界执行。在交付质量达标、人工纠偏可接受的前提下，降低完成合格交付的总成本。模型名称不是协议前提；“低成本”不等于能力不足，也不依据型号标签预判所有任务的表现。

父任务管理可以精简，但子任务交接必须充分。增加与当前任务直接相关的依据和示例，不增加通用禁令或每步审批。运行时的身份、材料校验、幂等性和状态规则继续保持确定，不依赖模型能力。

当前已具备：TaskContract v2、完整业务契约恢复、具体交接示例、可选模型及推理参数、operation_inputs，以及质量/人工/时间/usage 分开的 F 评测记录。生成器会传入非空业务字段，不要求子任务管理父任务账本。此次保留这些能力，不另建模板体系。

方案编写时的缺口（下述规则已实施，真实证据仍待补齐）：

- 父任务缺少按判断难度和管理成本选择委派范围的简短规则。
- 质量不合格后的纠偏、接管与换执行者路径不够明确，不能与平台 unknown 重试混为一谈。
- 现行真实验证默认 terra/high，F 方案却固定 GPT-6 父子组合；需区分测试目的并分别指定配置。
- F 仅有原生/插件两组，缺少主模型独立完成基线；旧插件提交和未解决答案泄漏的任务卡不能直接用于新批次。

## 1. 派发与交接规则

在现有 Skill 的契约编写部分补一段父任务判断，不增加每次必须填报的表格：

1. 先解决会实质改变实现方向的关键歧义；判断任务难度不能只看文件数或代码量。
2. 根据执行者已知能力、任务不确定性、交接和验收成本决定是否委派。简单且委派无收益的工作由父任务完成；不默认最低价或每次都选择最强模型。
3. 明确已定设计和子任务自主范围，将参考实现、必要背景、不可变接口、可验证结果及交回决定的条件写入现有字段。未决设计也可作为明确的调查任务派发，但不能伪装成已定实现任务。
4. 子任务负责执行、必要验证和证据交付；父任务负责契约、身份绑定、治理事实和最终验收。子任务不承担整套管理协议，主动再委派仍服从适用授权。

现有 task-handoff 参考补一个具体例子，展示“沿用某处理器错误格式、接口不变、补指定边界测试、数据库结构变动交父任务决定”。内容按需使用，不强制填满所有字段，不通过提示词长度衡量交接质量。

模型配置先遵守用户授权和实际工具说明。需要指定不同子模型时显式配置并核实；省略参数只表示未覆盖。当前 collaboration_turns 的完整继承与模型/推理覆盖不兼容，使用隔离或允许的有限继承并显式交接必要背景，不偷偷删除模型覆盖来通过校验。此处引用现有适配规则，不新增模型路由或硬编码型号。

## 2. 业务质量纠偏与生命周期边界

以实际产物、失败测试、越界修改和重复错误判断，不能仅依据子模型自报信心。正常审查不全算返工，新需求另记。

| 证据 | 父任务处置 |
| --- | --- |
| 缺少关键背景或约定不清 | 先修正交接，判断原执行者能否继续，不把交接缺陷直接归因于模型能力 |
| 明确、局部的实现错误 | 给出失败证据、预期行为和修复范围，按当前生命周期选择执行者 |
| 重复误解同一核心约束、纠偏无进展，或关键判断超出执行者能力 | 收回关键判断，重新限定任务；比较继续纠偏与接管/更换执行者的成本 |
| 平台调用结果 unknown、身份缺失或事实冲突 | 继续遵守现有恢复规则，不以业务返工为理由绕过身份核实、自动重发或重派 |

每次纠偏后按新证据判断是否值得继续；不设自动重试循环，也不为了填流程固定要求一次或多次返工。有明确任务预算时遵守预算，没有预算时不冒充已有硬上限。

### 进行中与终态后分别处理

- bound 且事实允许继续：沿用 exact target 通信或原范围 followup，不新增 identity；平台状态不明时先按现有规则处置。
- 已有明确终态：先如实登记；不得为了返工延迟登记、删除终态或重新激活原治理任务。terminal unknown 补记仅是事实登记，不是恢复执行许可。
- 终态后验收不合格：明确原交付未通过，记录缺陷与已有产物，由父任务接管，或显式收尾后为剩余修复建立新的独立生命周期。新任务由父任务基于确定证据作出业务决定，不是自动重派或对未知调用的重试。
- 更换执行者前核实旧执行已结束或停止；close 本身不证明停止或资源释放。旧执行状态无法确认且可能并发写入时，不把相同可写范围交给新执行者。
- 新交接写清当前工作区/基线、已有改动归属、失败证据、剩余范围和验收要求，不清除用户或旧执行者的成果，不要求新执行者从头重做。超出既有授权才向用户确认。

推荐继续不支持“同一 Agent 终态后的受管恢复”。如果后续需要这一能力，应另立设计解决新执行与迟到终态的关联，本方案不增加 attempt、消息日志或状态转换。

### 恢复期间的要求变更

现有 contract_summary 保存首次业务契约，后续消息不自动写入。父任务应在自身交接摘要中保留后续有效约定及来源；compact 后无法恢复这些约定时明确验收证据不足，不把原快照当作全部最新要求。真实恢复测试同时核对原始契约和后续要求的可恢复范围，不新增持久消息存储。

## 4. 验收和成本评测分开推进

### 运行与协作验收

程序正确性仍由现有回归验证；真实平台门槛核对实际受测提交、安装版本和父子配置。主要组合采用用户计划使用的强主模型与低成本子模型，不预先认定哪个型号更划算。

真实场景至少包括正常派发—消息—终态—验收—关闭，以及真实 compact 后恢复原始要求和验收依据。另用有明确缺陷的交付检查纠偏/接管规则是否可执行；不得伪造平台 unknown 来冒充真实恢复证据。未发生或无法核实的项目标为未验证。

### 收益评测

沿用 F 方案与记录模板，改为：

| 组别 | 用途 |
| --- | --- |
| S：主模型独立完成 | 衡量不委派的质量和总投入 |
| N：相同主子组合，原生协作 | 衡量委派本身的表现 |
| G：相同主子组合，插件协作 | 衡量插件流程的增量 |

三组保持主模型、业务起点、验收要求和必要信息一致；N/G 还固定子模型、继承、任务划分及工具权限。S 不强制照搬子任务划分。N/G 均需记录子任务显式配置，不能用同名请求替代实际配置证据。

按 S 对 N/G 判断委派收益，按 N 对 G 判断插件增量，不将二者混为一谈。保持独立工作区、结果隔离与顺序平衡；原生组的治理隔离、样本答案泄漏和数据来源仍需在正式运行前解决。

保留质量、父子 usage、父任务交接/审查/补工、用户纠偏、总耗时与缺失数据的现有口径。新增最少的决策记录：失败证据、纠偏/接管选择及理由、前后结果；不新增自动遥测。费用不可可靠取得时报告可观察量和缺失范围，不凭模型标签估算精确收益。

建议初轮只选择一个异构组合、一个代表任务，运行 S/N/G 各一次作为可行性先导，不宣称统计收益；之后再决定是否扩展。若沿用三个样本则至少九次业务运行，不能沿用旧六次/180 分钟总预算。正式次数、时间、人工投入、必要中断权限和扩样条件另行冻结并授权。

为避免纠偏策略成为混杂因素，首轮建议沿用 F 的保守规则：子任务终态后的缺陷由父任务在剩余预算内补工，N/G 不额外替换派发；进行中纠偏正常记录。更换执行者/模型的收益可另批评测，不能在某组失败后临时放宽政策。该评测限制不等于日常使用禁止父任务显式安排新的修复任务。

## 5. 实施顺序与完成标准

1. 用户确认本方案后，在一个开发任务中修改上述规则与评测材料；先对齐生命周期边界，再调整派发指导与模型组合描述。
2. 对照以下场景审阅：局部错误、缺背景、反复误解、终态后缺陷、unknown 且可能仍在写入、compact 丢失后续约定。每项应能确定允许的下一步、证据要求和授权边界，不能产生隐式终态恢复或无限返工。
3. 检查普通派发不新增必需工具调用，生成提示仍只传现有业务字段；模型选择服从实际工具和授权，核心 runtime 行为不变。
4. 运行 `git diff --check`、插件验证器与 Skill 验证器；运行直接关联的文档契约/示例检查。若现有测试断言依赖修改内容，更新并执行相关测试，不能只删断言来通过。不为自然语言判断新增脆弱字符串测试。
5. 若实际修改运行时代码，先补可靠复现测试，并完成 AGENTS.md 要求的全量 unittest、compileall 及验证器；否则不机械重复全量运行时检查。
6. 交付改动摘要、场景核对结果、实际验证和未验证项；不宣称异构模型收益已验证。部署事务及重启后的独立真实测试另经授权执行。

最初方案编写阶段的完成标准：方案与索引一致、引用路径可定位、推荐边界和待定项清楚；实施阶段另按上方步骤验收。

## 已采用边界与后续待定

- 实施推荐边界：保持单生命周期，不支持同一 Agent 终态后受管恢复；日常使用允许有据的接管或新修复任务，不自动重派。
- 评测推荐边界：先一个样本、一个异构组合、S/N/G 三次；首轮终态后统一由父任务补工。
- 真实运行前再确定：主子型号与推理强度、代表任务、插件精确版本、治理隔离方式、预算和合格标准。文档实施不依赖先选好具体模型；这些待定项不构成默认运行授权。
