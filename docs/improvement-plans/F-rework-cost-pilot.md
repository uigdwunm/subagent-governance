# F：返工与成本效果先导评测

日期：2026-09-16。状态：方案与材料准备；未开展实验。

用户同意按推荐方向准备：原生方式与最新版两组、先从本仓库提出候选、最多六次业务运行。当前授权不包含部署、关闭治理、真实派发、付费服务、提交合并或发布。运行预算是计划上限，不是运行授权。

## 目标与比较组

回答交付是否更容易验收、用户纠偏和父任务补工是否减少，以及总成本是否可接受。质量、人工投入和成本分别报告，不以总分抵消质量下降。

| 组别 | 处理方式 |
| --- | --- |
| N 原生 | 原生工具协作，正常业务交接与审查，不使用本插件治理流程 |
| G 新版 | 原生工具协作，使用提交 `2e9ccbd118c7ccb1051a623018561cd0d4378647` 的插件及 Skill |

两组业务基线、任务要求、验收量表、必要背景、工具权限、子任务划分和继承策略一致；业务信息相同，不强制提示字节相等。G 额外的材料准备、治理文档阅读、工具调用、等待及收尾计入成本。两组父任务整理交接材料的时间也计入。共用任务包的评测设计成本单列。

结论只归于整套流程的增量，不证明本轮相对旧版改进，也不单独归因到 A—E。旧插件组未选定；业务回放基线不是旧插件实验组，不安装历史版本。

## 样本与公平性

目标为三个任务各运行 N/G 一次：明确小修复（每组一个子 Agent）、有设计边界的功能（一个）、两个独立部分的集成任务（两个）。共六个独立父任务、最多八次初始子 Agent 派发。任务候选见[任务卡](F-rework-cost-task-cards.md)。不为凑齐数量强行拆分任务；不适合派发的简单任务优先由父任务完成，若需要实测该类任务须另定运行名额。

每次从同一份冻结的业务快照建立独立工作区和新任务，禁止共享修改、答案和另一组结果。不要把已安装插件指向受测代码；插件处理条件与业务材料分离。受测父任务和子 Agent 不得访问评审答案、后续修复提交及当前规划任务历史。仅在消息里要求不看答案不构成隔离证据。

运行前冻结：每个样本的基线完整 SHA、材料文件及 hash、业务要求、评分项、文件归属、父任务集成责任、两组完整提示、允许工具、运行顺序及记录版本。任何实质改动都形成新批次，不回改既有结果。重复数本批固定为每组每样本一次，不自动追加。

建议交错顺序：T1 N/G、T2 G/N、T3 N/G；这是预定平衡顺序，不声称已随机化。整个先导顺序执行，每次仅任务内部允许约定的并行。如果切换环境必须重启，切换成本单列，不能为方便把两组分别集中运行却隐去时段差异。环境不可比时停止配对。

## 正式运行前提

1. 选定真实代表性样本并解决任务卡中的泄漏、基线及规模问题；候选卡不能直接启动实验。
2. 明确且获授权的原生对照环境隔离方案，记录治理未启用的证据；不暗改 Hook、信任或缓存。现有环境仅走 unmanaged 不能证明没有 Skill 提示污染。控制方法目前未验证。
3. 新版部署单独取得明确授权，按项目要求在同一事务内写入、失败回滚和最终校验。命令结束后立即报告并停止，等待用户重启；真实验证在重启确认后的独立新任务执行。
4. 父任务与受测子 Agent 均显式 `gpt-6-astra` / `high`，子 Agent 建议显式 `fork_turns=none`。分别记录请求值、实际可取得值和证据，不能由请求值推断实际配置。未知标为 unknown；无法核实关键组间配置时不启动正式配对。
5. 按[兼容矩阵](../native-compatibility-matrix.md)分开记录 S/O/L/H/P。当前公开接口为 collaboration_turns 的声明证据；fork_context 当前客户端及 state-v12 链路未验证。历史真实结果不升级为本版 P；客户端精确版本、实际模型版本无法取得时记 unknown。
6. 独立门槛运行只检查当批实际需要的 native/Hook 链路和数据采集：本次返回 exact target、显式 confirm、终态登记、父方验收及关闭；两组均核对原生可用性和记录来源。门槛通过只证明所跑链路，不证明成本收益或全部兼容。无确定身份不重派补猜。

本规划任务不能作为受测父任务，不复用来源任务身份。今后所有治理命令只使用当次 SessionStart 权威 CLI 与 exact session_id；原生工具仍是唯一执行通道。不增加生命周期、自动重派或评测调度平台。

## 指标与事件口径

| 指标 | 固定口径 |
| --- | --- |
| 子交付 | 子 Agent 第一次声明可供父方验收的结果及当时快照 |
| 首次整体交付 | 父任务第一次向用户声明整体可验收的结果；此前修补不得漏记 |
| 最终验收 | 固定预算内补工后，由固定评审者按原始业务量表验收；区分通过、不通过、无法验证、未到达 |
| 用户纠偏 | 一次反馈批次计一次，另记独立问题数；实际阅读、解释、复核投入由用户简短记录，缺失不当零 |
| 父任务投入 | 澄清、审查、修代码、补测试、集成；每段标正常工作或缺陷返工，不把所有审查都算补工 |
| 全链路耗时 | 父任务收到冻结任务包至最终验收或停止；同时记录首次交付时间、用户等待及可观察工具/Agent 等待 |
| token | 可可靠归属的父子调用 usage，注明输入、输出、缓存字段语义与来源；未知为缺失，估算与实测分开 |
| 失败与停止 | 所有已开始运行保留，包括预算耗尽、平台错误、无法验收、中止及条件失配 |

时间使用带时区的实际时间戳。并行子 Agent 时长不相加冒充墙钟时间；重叠活动标记重叠，不重复计算父任务总投入。治理耗时是总时间的一部分，不再额外加一次。账号总用量不能代替单次运行 token；不把文本字数冒充 token，不据不完整 usage 给出精确全链路成本。平台未暴露真实执行时长时，只报告观察区间。

返工事件允许多个原因：需求交接、设计偏离、遗漏背景、集成冲突、身份/终态治理错误、普通实现错误、平台故障、需求变化、原因未明。每项附证据及归因把握度，多标签事件只计一次投入。新需求单列，不能倒改首次通过口径；改变关键范围则结束原配对，另行决策。

每张任务卡冻结目标行为、边界与回归、设计与范围、组合结果、可复核证据五类业务标准；每类可用多个具体检查项。逐项通过/不通过/无法验证，所有关键项通过才算整体通过。测试绿、completed、close 都不是业务通过。

首次和最终产物尽可能去掉组名后交给同一评审者，评审者不改结果；无法盲评则明确记录。评审按同一量表给一次集中反馈，两组不互看反馈。用户评审与父任务自检分开。子 Agent 终态后统一由父任务在剩余预算内补工，不为评测增加受管恢复或替代派发。

## 预算与停止

- 六次业务运行每次最多 30 分钟墙钟窗口，共最多 180 分钟；首次整体交付后补工最多 15 分钟且仍包含在该 30 分钟内。等待用户也计入窗口并单列，因此先预约评审窗口，避免把用户离线误判为模型性能差异。
- 门槛验证另留最多 20 分钟，运行名额及具体工具调用随正式授权冻结；不当作业务样本。部署、重启、准备与分析耗时另列，不藏入零成本，也不承诺整个项目只需 200 分钟。
- 用户标注与复核总投入最多 60 分钟；每次最多一轮集中反馈。材料准备和评审者投入单列。
- 不额外购买额度、调用付费 API、自动扩样或自动重跑。token 暂无可靠硬上限；若用户要求精确 token 或金额上限且平台不可执行该限制，则不启动。
- 耗尽预算、真实平台不兼容、不可恢复阻塞、必要身份未知、越界决策或无法保证公平时停止受影响运行。系统性失败暂停整批，不选择性排除失败样本。
- 正式授权需包括预算到期时对已绑定 exact target 的必要中断。中断结果未知如实记录；停止计时不证明资源释放，后续可观察的消耗追加到停止后成本，不伪装硬保证。
- 修复环境后的重测必须另行授权，保留原记录；不用多 attempt、自动恢复身份或新增持久化机制绕过。

## 结果与后续决策

使用[记录与结果模板](F-rework-cost-record-template.md)，按每对原始结果及绝对差值报告；分母为已开始次数，同时列计划未开始数。相对变化遇原生值为零记不适用。不要把三种不同难度任务汇成精确总体收益率，不声称统计显著或因果已证实。

收益门槛待样本选定后、运行前冻结。讨论默认值：新版无新增关键质量失败，至少两对的用户纠偏投入或父任务返工下降，且配对总运行时间增幅不超过 20%。这只是是否值得扩测的候选标准，不是已批准的上线标准。任一维度缺失都保留，不以“无记录”声称无返工。六次都无返工只能表明样本未测出差异。

最终对具体改动分别列支持性事件、额外负担、未触发/证据不足，以及建议保留、调整或继续观察的理由。整组对照不能证明单项有效；允许无收益和负面结果。改动建议不是自动新增规则或实施授权。
