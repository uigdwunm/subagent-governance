# F：返工与成本效果先导评测

更新：2026-09-17。状态：异构模型三组方案与材料准备；未开展实验。

当前授权为规则和评测文档实施，不包含部署、关闭治理、真实派发、付费服务或发布。旧两组/六次预算不适用于本批；下列候选预算须在正式运行前冻结并授权。

## 目标与比较组

回答交付是否更容易验收、用户纠偏和父任务补工是否减少，以及总成本是否可接受。质量、人工投入和成本分别报告，不以总分抵消质量下降。

| 组别 | 处理方式 |
| --- | --- |
| S 独立 | 相同主模型独立完成，不派发子 Agent、不使用插件治理 |
| N 原生 | 原生工具协作，正常业务交接与审查，不使用本插件治理流程 |
| G 新版 | 原生工具协作，使用本批冻结的插件完整提交及 runtime digest，部署后核实实际加载版本 |

三组主模型及推理强度、业务基线、任务要求、验收量表、必要背景和业务工具权限一致；N/G 另固定子模型、推理、子任务划分及继承策略，S 不强制模拟子任务划分。业务信息相同，不强制提示字节相等。G 额外的材料准备、治理文档阅读、工具调用、等待及收尾计入成本。各组父任务整理材料的时间也计入。共用任务包的评测设计成本单列。

S 对 N/G 回答委派收益，N 对 G 回答插件流程增量；不混合这两类结论。插件结论只归于整套流程的增量，不证明本轮相对旧版改进，也不单独归因到 A—E。旧插件组未选定；业务回放基线不是旧插件实验组，不安装历史版本。

## 样本与公平性

首轮选择一个代表任务、一个强主模型与低成本子模型组合，S/N/G 各一次，共三个独立父任务。N/G 初始子 Agent 数按冻结任务卡相同指定，不自动追加。任务候选见[任务卡](F-rework-cost-task-cards.md)，不为凑样本强行拆分；简单任务由 S 独立完成的收益也应如实记录。

每次从同一份冻结的业务快照建立独立工作区和新任务，禁止共享修改、答案和另一组结果。不要把已安装插件指向受测代码；插件处理条件与业务材料分离。受测父任务和子 Agent 不得访问评审答案、后续修复提交及当前规划任务历史。仅在消息里要求不看答案不构成隔离证据。

运行前冻结：每个样本的基线完整 SHA、材料文件及 hash、业务要求、评分项、文件归属、父任务集成责任、三组完整提示、允许工具、运行顺序及记录版本。任何实质改动都形成新批次，不回改既有结果。重复数本批固定为每组每样本一次，不自动追加。

运行前预定三组顺序并记录，单样本不声称顺序效应已平衡；后续扩样可轮换 S/N/G、N/G/S、G/S/N。顺序执行，每次仅任务内部允许约定的并行；切换环境所需重启成本单列。条件不可比时停止相应比较。

## 正式运行前提

1. 选定真实代表性样本并解决任务卡中的泄漏、基线及规模问题；候选卡不能直接启动实验。
2. 明确且获授权的 S/N 对照环境隔离方案，记录治理未启用的证据；不暗改 Hook、信任或缓存。现有环境仅走 unmanaged 不能证明没有 Skill 提示污染。控制方法目前未验证。
3. 新版部署单独取得明确授权，按项目要求在同一事务内写入、失败回滚和最终校验。命令结束后立即报告并停止，等待用户重启；真实验证在重启确认后的独立新任务执行。
4. 正式运行前由用户选定或批准父子模型与推理配置，分别显式指定；N/G 使用相同异构组合，子 Agent 建议隔离继承，S 使用相同主模型。分别记录请求值、实际可取得值和证据，未知标 unknown；无法核实关键组间配置时不启动正式比较。型号不是协议前提，不用请求值推断实际配置。
5. 按[兼容矩阵](../native-compatibility-matrix.md)分开记录 S/O/L/H/P 证据等级（其中 S 为声明证据，不是独立实验组 S）。既有 state-v12 真实记录仅证明所载安装版本和 terra/high 组合，不能代替本批受测版本及异构组合；其他接口需按实际证据标记。客户端精确版本、实际模型版本无法取得时记 unknown。
6. 独立门槛运行只检查当批需要的链路和数据采集：G 检查本次返回 exact target、显式 confirm、终态登记、父方验收及关闭；N 检查原生派发、返回身份、通信、结束与业务验收，不调用治理 CLI；S 检查独立执行与记录条件。门槛通过只证明所跑链路，不证明成本收益或全部兼容。无确定身份不重派补猜。

本规划任务不能作为受测父任务，不复用来源任务身份。今后所有治理命令只使用当次 SessionStart 权威 CLI 与 exact session_id；原生工具仍是唯一执行通道。不增加生命周期、自动重派或评测调度平台。

## 指标与事件口径

| 指标 | 固定口径 |
| --- | --- |
| 子交付 | 子 Agent 第一次声明可供父方验收的结果及当时快照 |
| 首次整体交付 | 父任务第一次向用户声明整体可验收的结果；此前修补不得漏记 |
| 最终验收 | 固定预算内补工后，由固定评审者按原始业务量表验收；区分通过、不通过、无法验证、未到达 |
| 用户纠偏 | 一次反馈批次计一次，另记独立问题数；实际阅读、解释、复核投入由用户简短记录，缺失不当零 |
| 父任务投入 | 澄清、审查、修代码、补测试、集成；每段标正常工作或缺陷返工，不把所有审查都算补工 |
| 全链路耗时 | 父任务收到冻结任务包至最终验收或停止；同时记录首次交付时间、用户等待及可观察工具/Agent 等待 |
| token | 可可靠归属的父子调用 usage，注明输入、输出、缓存字段语义与来源；未知为缺失，估算与实测分开 |
| 失败与停止 | 所有已开始运行保留，包括预算耗尽、平台错误、无法验收、中止及条件失配 |

时间使用带时区的实际时间戳。并行子 Agent 时长不相加冒充墙钟时间；重叠活动标记重叠，不重复计算父任务总投入。治理耗时是总时间的一部分，不再额外加一次。账号总用量不能代替单次运行 token；不把文本字数冒充 token，不据不完整 usage 给出精确全链路成本。平台未暴露真实执行时长时，只报告观察区间。

返工事件允许多个原因：需求交接、设计偏离、遗漏背景、集成冲突、身份/终态治理错误、普通实现错误、平台故障、需求变化、原因未明。每项附证据及归因把握度，多标签事件只计一次投入。新需求单列，不能倒改首次通过口径；改变关键范围则结束原配对，另行决策。

每张任务卡冻结目标行为、边界与回归、设计与范围、组合结果、可复核证据五类业务标准；每类可用多个具体检查项。逐项通过/不通过/无法验证，所有关键项通过才算整体通过。测试绿、completed、close 都不是业务通过。

首次和最终产物尽可能去掉组名后交给同一评审者，评审者不改结果；无法盲评则明确记录。评审按同一量表给一次集中反馈，三组不互看反馈。用户评审与父任务自检分开。N/G 进行中可以按失败证据纠偏，记录理由与结果；终态后统一由父任务在剩余预算内补工，不增加替代派发或更换模型，S 在相同规则下补工。这是首轮控制条件，不限制日常有据的新修复任务；执行者升级收益另批评测。

## 预算与停止

- 候选预算：三次业务运行每次最多 30 分钟墙钟窗口，共最多 90 分钟；首次整体交付后补工最多 15 分钟且仍包含在该 30 分钟内。等待用户也计入窗口并单列，因此先预约评审窗口，避免把用户离线误判为模型性能差异。
- 门槛验证另留最多 20 分钟，运行名额及具体工具调用随正式授权冻结；不当作业务样本。部署、重启、准备与分析耗时另列，不藏入零成本，也不承诺整个项目只需 110 分钟。
- 候选用户标注与复核总投入最多 30 分钟；每次最多一轮集中反馈。材料准备和评审者投入单列。
- 不额外购买额度、调用付费 API、自动扩样或自动重跑。token 暂无可靠硬上限；若用户要求精确 token 或金额上限且平台不可执行该限制，则不启动。
- 耗尽预算、真实平台不兼容、不可恢复阻塞、必要身份未知、越界决策或无法保证公平时停止受影响运行。系统性失败暂停整批，不选择性排除失败样本。
- 正式授权需包括预算到期时对已绑定 exact target 的必要中断。中断结果未知如实记录；停止计时不证明资源释放，后续可观察的消耗追加到停止后成本，不伪装硬保证。
- 修复环境后的重测必须另行授权，保留原记录；不用多 attempt、自动恢复身份或新增持久化机制绕过。

扩展为三个样本时至少九次业务运行，须重新冻结预算和次数，不套用旧六次/180 分钟安排。当前预算为讨论值，正式运行授权与可执行性确认缺一不可。

## 结果与后续决策

使用[记录与结果模板](F-rework-cost-record-template.md)，分别报告 S/N/G 原始结果、S 对 N/G 及 N 对 G 的绝对差值；分母为已开始次数，同时列计划未开始数。相对变化遇原生值为零记不适用。不要把三种不同难度任务汇成精确总体收益率，不声称统计显著或因果已证实。

首轮只判断可行性，不宣称统计收益。运行前冻结质量关键项、允许的时间/人工投入增幅及扩测条件；至少要求无新增关键质量失败、数据可比，并能说明管理与返工成本。结果允许无收益或负收益。各维度缺失保留 unknown；三次均无返工仅说明样本未测出差异，不能证明治理降低返工。

最终对具体改动分别列支持性事件、额外负担、未触发/证据不足，以及建议保留、调整或继续观察的理由。整组对照不能证明单项有效；允许无收益和负面结果。改动建议不是自动新增规则或实施授权。
