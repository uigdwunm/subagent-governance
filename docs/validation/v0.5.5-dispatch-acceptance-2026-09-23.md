## 实际结果

- 新任务的 SessionStart 注入指向开发安装版的 CLI，初始 exact Session 账本为空。
- `--prepare-dispatch` 返回 `expires_at=1790213752`，距准备时约 900 秒。子 Agent 只读读取 `schemas/governance-semantics.schema.json`，报告第 317 行的 `prepared_expiry_seconds` 为 `900`。
- 原生 `spawn_agent` 返回完整 canonical target；使用该回执完成 `--confirm-dispatch` 后任务为 `bound`。收到子 Agent 完成通知后登记 `terminal/completed`，父任务验收并关闭，最终账本为 `closed`，没有 reconcile 或 unknown 事实。仓库无文件改动。
- 父任务和子 Agent 的运行记录分别显示 `gpt-6-sol/high`、`gpt-6-luna/high`。本次用户可见派发说明没有重复披露。

## 证据边界

- `fork_turns=none` 是原生派发参数；子 Agent 运行元数据未独立记录实际继承配置，因此实际隔离方式标为未验证。本次结果不用于要求该配置可比的正式收益对照。
- 绑定成功证明本次 claim 已在账本中成立，但原生工具回执未展示 Hook 的独立 `code=claimed` 文本。
- 未等待真实 15 分钟过期，也未通过真实平台触发 `preparation_expired`。该边界由开发仓库测试覆盖，不能称为真实平台已验证。
- 本次没有叠加 `$solution-design` 的固定启动区块，因此只能证明普通派发没有重复披露，不能证明跨 Skill 去重已经通过真实测试。
- 以上证据对应本机开发安装版与当次 Codex 运行环境；公开 `v0.5.5` 标签及 Marketplace 安装后的行为需另行验证，不能由本报告推断。
