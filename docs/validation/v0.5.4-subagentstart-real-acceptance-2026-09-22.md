# v0.5.4 SubagentStart 独立真实验收（2026-09-22）

结论：在已信任新增 Hook 后，隔离 supervisor 的真实启动注入、嵌套 worker 的受管派发、精确身份绑定、中断观察与两级关闭通过。此验收使用本机开发安装版 `0.5.3+codex.20260921003336`；相较受测运行包，公开 `v0.5.4` 的运行时代码只改变插件 Manifest 的版本字段，未作为该标签重新安装测试。

## 问题与修复边界

旧版只注册 `SessionStart` 和 spawn `PreToolUse`。隔离 supervisor 没有收到 Hook 权威 Session 与 CLI，按 Skill 在 `prepare/spawn` 前停止。开发仓库新增 `SubagentStart` 注册与只读上下文输出；Hook 的 `session_id` 是父会话 ID，不以子 Agent 的 thread/agent ID 替代。子任务启动时不读取共享账本，也不因看见记录而接管父级或兄弟任务。

首次重启后独立任务仍停在相同位置。只读 `hooks/list` 随后查明：新版 `SubagentStart` 为 `enabled=true, trustStatus=untrusted`，而原有两个 Hook 已获信任。用户审查并信任该 Hook 后，回读同一当前哈希为 `trusted`，再次使用新角色验收；没有修改代码、伪造 Hook 或手工向子任务传递父 Session。

## 真实结果

独立测试父任务只派发一个新 supervisor。原生返回完整 canonical target，父任务 `confirm` 返回 `bound`。supervisor 的原始运行记录出现来自 `SubagentStart` 的开发者上下文，包含 Hook 权威 exact Session 与已安装 CLI entrypoint。它据此准备并原生派发唯一隔离 worker，再以原生返回的完整嵌套 target `confirm` 为 `bound`。worker 的原始运行记录也包含自身的启动 Hook 注入。

worker 发出就绪消息并保持运行。supervisor 针对绑定的精确 target 中断；中断调用只报告操作前 `previous_status=running`，故将该调用回执记为 `unknown`。之后平台对同一 target 的观察为 `interrupted`，以该确定事实登记终态并关闭 worker。父任务收到 supervisor 的明确完成通知后关闭 supervisor。最终 worker 为 `closed/interrupted`、supervisor 为 `closed/completed`，两者 `next_action=none`，没有未关闭的测试角色。

父任务原始 `turn_context.model/effort` 为 `gpt-6-sol/high`；supervisor 和 worker 均为 `gpt-6-luna/high`。这核实 Codex 运行元数据，不独立证明 provider 后端物理模型。两次原生派发参数都明确设置 `fork_turns=none`；运行记录没有单独回显最终继承配置，只能依据派发请求和子任务可见初始上下文判断。测试未评估成本收益、崩溃恢复或其他未发生的平台异常。

本报告使用角色别名而不公开测试 Session、任务引用、原生 target 或本机路径。原始回执和逐行运行记录留在执行环境中；本报告的通过范围限于这次已信任 Hook 的 macOS 宿主实验。
